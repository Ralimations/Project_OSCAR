What is O.S.C.A.R.?

A fully offline agentic system that transforms a constrained computer into a multimodal interactive hub without relying on cloud services.


  • 🔒 Offline-First: Built around local models, local databases, and on-device routing with no required cloud path.
  • 💻 Constraint-Resilient: Designed for modest Windows laptop hardware with CPU-first inference and deterministic fallbacks.
  • 🌐 Multimodal Orchestrator: Combines gestures, wake-word-triggered audio capture, screenshots, and OCR history inside one local control loop.

The Core Subsystems (1/2)

🧠

BRAIN (Planner)

Structured action planner with deterministic fallbacks. The active profile targets a local Ollama-hosted Gemma model, with optional CPU-local model loading paths retained in the codebase.

👁️

EYES (Vision)

Continuous MediaPipe Tasks hand and face tracking with startup calibration, pinch-to-click, vertical scroll gestures, and head-pose-based yes/no detection logic.

The Core Subsystems (2/2)

👂

EARS (Hearing)

Local wake-word listening and raw utterance capture are implemented through openWakeWord. The STT path is scaffolded for Faster-Whisper-style local transcription and still needs end-to-end validation on device.

⚡

VOICE & ACTION

Threaded action dispatch uses PyAutoGUI-backed desktop controls and app-aware shortcuts. A Piper voice layer exists as an optional local output path with text fallback when not configured.

AGENTIC REASONING

GenAI: The Local Brain

Powering the "Brain" module with high-speed, local LLM execution:

  • ⚡ Active local model profile: Current runtime is configured around a local Ollama-served Gemma profile, with smaller CPU-local model paths available for experimentation.
  • 📜 Structured Outputs: Enforces strict JSON schemas for reliable desktop action sequences.
  • 🔄 Fallback Intelligence: If the model path is unavailable or returns invalid output, OSCAR falls back to deterministic action planning instead of stalling the pipeline.
SENSORY FUSION

VLM & Multimodal

Fusing vision, memory, and desktop context into a single cohesive stream.

Visual Scene Understanding

The current visual route captures screenshots and can forward them to a local vision-capable backend when one is configured. It is not yet a fully validated live webcam VLM stack.

Multimodal Routing

Routes between direct desktop actions, screenshot-assisted inference, and local OCR history lookup depending on what signal is available in the current interaction.

Key Capabilities

  • 🔄 Fallback Engine: Preserves responsiveness by favoring direct actions and deterministic planning when the model path is unavailable or unnecessary.
  • ✋ Gesture-First Interaction: Live gesture control is implemented with calibration, cooldown handling, and asynchronous action dispatch. Head yes/no exists in logic but is still being tuned for reliable UX.
  • 🕰️ OCR Memory Route: OSCAR can query a local SQLite OCR history store for retrospective lookup when a valid local database is present.
  • 🛠️ Desktop Control Layer: Click, scroll, keypress, hotkey, and text-entry actions are exposed through a threaded controller that can also run in sandbox-only mode.

THE EDGE ENGINE

Tech Stack

Models & AI

  • 🧠 Local LLM profile: Ollama-served Gemma profile in current config, with optional smaller CPU-local model paths in code.
  • 👁️ Vision backend seam: Screenshot-to-model routing is implemented when a local vision-capable backend is available.
  • 👂 openWakeWord: Local wake-word detection and utterance capture.
  • 🗣️ Piper: Optional local speech output with text fallback.

Core Infrastructure

  • 💻 Python 3.13: Local orchestrator runtime.
  • 🖼️ MediaPipe Tasks: Hand and face landmark tracking.
  • 🗄️ SQLite OCR history: Local retrospective lookup path compatible with Screenpipe-style data.
  • ⚙️ PyAutoGUI: Desktop automation and screenshot capture.

OSCAR in Action

Accessibility

Gesture-first desktop control creates a practical base for accessibility-focused workstation interaction, with head-confirmation logic under active tuning.

Developer Flow

Screenshot capture, OCR recall, and direct desktop actions support low-friction local assistance without depending on remote services.

Corporate Privacy

The architecture is aimed at privacy-sensitive and air-gapped workflows by preferring local models, local automation, and local data sources.

Why it Matters

Project O.S.C.A.R. shows how far a local-first assistant can go by combining calibrated gesture input, wake-word-triggered audio capture, screenshot context, OCR memory, and deterministic desktop control inside one offline-oriented runtime.
